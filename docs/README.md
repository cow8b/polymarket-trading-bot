## 文档规范

1. **位置**：除根目录的 `README*` 与 `AGENTS.md` 外，所有项目文档统一放在
   `docs/` 下；文档配图放 `docs/assets/`。不要在源码目录里散落 `.md` 文件。
2. **命名**：文件名使用大写下划线式英文（如 `HANDOVER_AUDIT.md`），便于跨平台
   引用；一个主题一个文件，避免万物塞进同一篇。
3. **语言**：正文使用简体中文；代码标识符、命令、路径、专有名词保留英文原文。
4. **开头约定**：每篇文档以一段引用块开头，说明文档用途、适用范围和最近一次
   实质更新的日期（写绝对日期，不写"上周/最近"）。
5. **与代码同步**：改变行为的 PR 必须同步更新受影响的文档（含本索引与
   `AGENTS.md`）；文档里引用的脚本、参数、路径必须真实存在——接手审计发现的
   主要文档问题就是死链与过期描述。
6. **索引登记**：新增文档必须在上方索引表登记一行（文件名 + 一句话用途）。
7. **不入库的内容**：`.env` 值、私钥、凭据、本地数据库快照不得写入任何文档；
   示例配置一律用占位符。
